# ZIF, audio, UI, and shader auxiliary asset investigation

Status: P1-18 evidence-backed classification and routing contract.

## Scope and evidence boundary

This investigation classifies the installed-client corpus and the legacy read-only source. It
does not link legacy code, import assets into UE, infer missing runtime state, or copy source
assets into `Rebuild`. The machine-readable evidence is regenerated by
`Tests/Contract/Test-AuxiliaryAssetInvestigation.ps1`.

The installed corpus contains:

| Family | Files | Bytes | Classification |
|---|---:|---:|---|
| `.zif` | 841 | 4,565,902 | BOM-less UTF-8 XML zone-navigation records |
| `.wav` | 450 | 54,949,730 | RIFF/WAVE, uncompressed PCM |
| `.mp3` | 64 | 124,002,521 | MPEG audio streams, with or without ID3v2 prefix |
| UI Package files | 4 | 259,168 | Package 2.0/3.0 directories containing 2,890 `QTexture` objects |
| Material Package files | 10 | 1,359,988 | Package 2.0/3.0 directories containing 14,390 `QPhongShader` objects |
| `.ttf` | 3 | 23,475,828 | font binaries; rights review required before product import |

No installed `.fx`, `.hlsl`, `.vsh`, `.psh`, `.vert`, `.frag`, `.ui`, `.swf`, `.otf`,
`.fnt`, or `.ogg` file was found. Absence in this corpus is not proof that another authorized
client build cannot contain one.

## ZIF: zone navigation XML

Every installed `.zif` file parses as XML with a `Zone` root and the four sections
`PathIndex`, `DirInfo`, `zPolygon`, and `AllPath`. All are BOM-less. The corpus is split between
`Table/pathInfo` (806 files) and `Table/zoneInfo` (35 files).

The legacy `QAutoPath::loadPathInfo` reader establishes the field meanings:

- `PathIndex/A@id` references path nodes from the companion `.path` document;
- four `DirInfo/A` entries represent north, east, south, and west connectivity, using
  `inNode` and an optional outbound `node`;
- `zPolygon/Poly` records polygon/segment shape, center, radius, and ordered `ID` vertices;
- `AllPath/A` stores a direction-pair route and the ordered node list `n0..nN`.

The 841 files contain 47,988 path-index references, 3,364 direction entries, 6,712 polygons,
77,582 polygon vertex references, and 1,287 precomputed inter-direction paths. `zone1308.zif`
is the largest by bytes and by XML element count. ZIF therefore belongs to world-navigation
data, not terrain geometry, UI, or a generic archive.

Route: preserve XML byte hashes, parse with a bounded XML reader, bind against the matching
`.path` document, validate references and zone bounds, then emit a versioned navigation graph.
Do not import it directly into UE NavigationSystem and do not silently repair disconnected
links. This work belongs after the P1 intermediate contract and before full world/navigation
conversion.

## Audio: PCM effects and MPEG music

All 450 WAV files have valid `RIFF`/`WAVE` signatures and parseable chunk bounds. Every `fmt `
record is format code 1 (PCM), 16-bit, with this distribution:

| Channels | Sample rate | Files |
|---:|---:|---:|
| 1 | 22,050 Hz | 32 |
| 1 | 44,100 Hz | 406 |
| 2 | 22,050 Hz | 6 |
| 2 | 44,100 Hz | 6 |

The legacy Miles Sound System adapter derives effect paths as
`Resource/Sound/<package>/<object>.wav`, supports 2D and distance-limited 3D playback, and
opens music as a stream path. That behavior is evidence only; Miles does not enter the new
runtime.

Of the 64 MP3 files, 39 start with ID3v2 and 25 start directly with an MPEG frame. The files
are music/stream inputs, not `QSound` effect payloads. P1-18 does not decode or transcode them.

Route: import validated PCM WAV effects through a later Editor-only UE audio pipeline; retain
channel/rate/loop/attenuation metadata separately from source bytes. Decode MP3 music offline
to a lossless intermediate only after codec, content-rights, loudness, and loop-boundary review.
The original byte hash remains provenance; decoded outputs are generated assets and never a
replacement for the evidence file.

## UI: texture assets plus code-defined behavior

The four installed `Packages/UI` files parse through the existing Package 2.0/3.0 reader and
contain exactly 2,890 objects, all classed `QTexture`. They are texture metadata containers;
the associated pixel payload remains in the QTX resource path already handled by
`TMXY.Texture`.

No separate installed `.ui` or `.swf` layout corpus exists, and the general XML corpus is data
and configuration rather than a UI layout format. Legacy `QGUIFrame.h/.cpp` supplies behavioral
evidence for frame composition and interaction, but must not be compiled into the new client.

Route: reuse the Package normalized tree and QTX conversion for UI images. Reconstruct layout,
focus, input, localization, and accessibility as native UE UI behavior from verified screenshots,
scripts, configuration, and legacy behavior evidence. Do not represent the 254,650-byte legacy
`QGUIFrame.cpp` as a new monolithic UI class. The three TTF files remain evidence-only until
font ownership and redistribution rights are approved.

## Shader: material semantics, not shader source

The installed corpus contains no loose shader source or bytecode extension. All ten
`Packages/Material` files parse through the existing Package reader and contain exactly 14,390
objects, all classed `QPhongShader`. Legacy serialization identifies texture references and
parameters including diffuse, bump, blend, specular power/shine, parallax, self illumination,
mask, reflection, UV transform, transparency, and quick-draw state. Legacy source also defines
fur, subsurface-like, anisotropic, and geometry-effect classes, but none occurs in the installed
Material package directory.

Route: extend Package object-body semantics for the observed `QPhongShader` properties, cluster
material combinations, then map them into a small reviewed family of UE material masters and
instances. Preserve unsupported fields in the intermediate record. Visual equivalence must be
accepted by golden renders; legacy D3D9 render state or class names are not treated as UE shader
source.

## Priority and ownership route

| Priority | Family | Next contract | Primary risk |
|---:|---|---|---|
| 1 | UI textures and material semantics | P1-19 versioned records, then P1-22/P3 visual slices | reference binding, color/alpha, PBR mismatch |
| 2 | PCM WAV effects and MP3 music | P1-19 audio manifest, then Editor-only audio importer | rights, loop metadata, attenuation, lossy decode |
| 3 | ZIF navigation | versioned graph after P1-19, then full world dependency work | cross-file references and source disconnections |
| 4 | UI layout/behavior and fonts | golden UI reconstruction after importer foundation | no standalone layout corpus; font redistribution |

P1-18 ends at classification and routing. It intentionally creates no empty `TMXYUI`,
`TMXYNet`, shader, audio, or navigation runtime module.
