# UE Golden Terrain Import

P1-26 proves the TER-to-UE interchange boundary with three real neighboring `world` tiles. The
fixture is generated by the locked non-root Clang 21 `TMXY.Terrain` exporter and contains only
small deterministic typed planes and metadata. The original Level package and TER files remain
read-only reference evidence and are not copied into the repository.

## Physical scale

The matching `Level/world` package contains `world.QLEVEL.zoneSize = 252` and
`world.terrainInfo.tileNum = 63`. Legacy `QTerrain::init` applies
`zoneSize / tileNum = 4` uniformly to X, Y, and height. The established legacy-to-UE contract then
converts meters to centimeters. The importer therefore uses exactly 400 cm per Cell, 25,200 cm per
Tile edge, and `height_source_units * 400` for UE Z. No value is inferred from the TER filename or
from its height range.

## P1 representation boundary

The Editor-only importer creates deterministic `UStaticMesh` proof assets with 4,096 source
vertices, 7,938 upward-facing triangles, one normalized UV channel, and the four source layer
alphas in vertex color RGBA. This is an interchange and geometry proof, not the P3 runtime terrain
architecture decision. P3-11 still owns the measured Landscape-versus-custom-renderer ADR.

The Tile uses the legacy X-forward, Y-right, Z-up orientation directly. `world_001_001` is compared
with its right and bottom neighbors without reversing edge sample order. The source has 16 right
edge differences (maximum 12.80364990234375 cm after scale) and 10 bottom-edge differences
(maximum 1.9155502319335938 cm). P1-26 preserves and reports those existing values; it does not
silently weld evidence.

## Enforcement

`TMXY.Importer.Terrain` verifies the Manifest, source-evidence file, and all 12 declared artifact
hashes before any package write. It then checks every imported height and layer sample, every
triangle winding, exact scale and direction, both 64-sample adjacency pairs, invalid-hash rejection,
and byte-identical content-addressed reimport of all three assets.

Run the focused gate after UE Automation evidence exists:

```powershell
& 'E:\QQXYCodeDev\Rebuild\Tests\Contract\Test-UETerrainImport.ps1' -RequireAutomationEvidence
```

The generated Automation report is validated by
`Contracts/data-schema/ue-terrain-import-report-v1.schema.json` and the focused result is written to
`Data/BuildBaseline/p1-26-ue-terrain-import.json`.
