# ADR-013：工程结构与代码质量门禁

- 状态：Accepted
- 日期：2026-08-26

## 决策

新工程采用 Domain → Application/Ports → Adapters → Apps 的单向依赖，第三方类型不得进入领域层。CI 对所有手写代码强制执行格式、静态分析、测试、架构依赖和规模限制。

硬限制：

- 手写 `.h/.hpp` 不超过 500 行；
- 手写 `.c/.cc/.cpp` 不超过 1000 行；
- 函数不超过 100 个逻辑行；
- 圈复杂度不超过 15；
- 嵌套深度不超过 4；
- 生成代码和第三方代码只能在显式豁免目录。

详细规则以 `Docs/Standards/ENGINEERING-STANDARD.md` 为准。

## 原因

旧工程存在职责集中、平台/数据库类型穿透和巨型文件风险。如果不在第一天通过自动门禁限制，后期拆分成本和回归风险会快速增长。

## 后果

- 架构和拆分属于每个功能的完成条件，不作为后续“重构阶段”。
- 超限代码不能合入主分支。
- 临时豁免必须有负责人、拆分计划和到期日期；到期后 CI 失败。
