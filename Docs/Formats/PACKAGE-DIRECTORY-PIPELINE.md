# Package 2.0/3.0 目录处理顺序

## 定论

P1-07 将 Package 2.0 和 3.0 的目录处理收敛到 `package_directory_codec` 唯一实现。当前证据支持以下分类：

- 目录层执行固定、无状态、可逆的字节置换与按位取反；这是混淆，不是密码学加密。
- 目录层不需要 key、口令、Token、证书或其他 Secret。
- 目录层没有观察到压缩包装；变换后立即得到可按固定前缀和记录 Schema 解析的目录。
- 容器层不变换对象 body，只按已验证的 offset/size 暴露有界原始字节 span。
- 对象 body 自身的序列化、编码、压缩和内部校验由后续具体类/资源格式合同决定，不能由容器结论代替。

因此不得把 2.0/3.0 目录算法命名为 AES、加密或 Secret 解锁，也不得把“目录可读”写成“所有对象资源已解码”。

## 强制处理顺序

```text
读取并验证外层版本/目录长度
  → 按 2.0 或 3.0 选择目录 codec
  → 执行固定可逆目录混淆解码
  → 验证 14-byte 前缀、计数和记录
  → 验证对象区间连续覆盖到 EOF
  → 向具体对象 codec 提供只读有界 body span
```

任何具体对象 codec 都不得绕过容器读取器直接信任文件内 offset/size。目录解码失败时不得尝试猜测版本、自动切换算法或把未验证字节交给对象反序列化器。

## 算法边界

2.0 完整四字节组的解码是 `~E2 ~E3 ~E0 ~E1`，尾部逐字节取反；同一函数也是编码逆变换。3.0 完整组为 `~E2 ~E3 E0 ~E1`，尾部余 1/2/3 bytes 分别为 `E0`、`E0 ~E1`、`~E2 E0 ~E1`，编码器执行对应逆置换。

共享 codec 同时提供解码偏移到原文件编码偏移的映射。2.0/3.0 读取器不再维护各自的私有变换副本，避免算法漂移。

## 全样本往返证据

| 属性 | 冻结值 |
|---|---:|
| Package 2.0 文件 | 22 |
| Package 3.0 文件 | 140 |
| 目录总字节 | 5,364,459 |
| 记录总数 | 118,711 |
| 容器文件总字节 | 42,117,271 |
| 解码目录集合 FNV-1a 64 | `7c86de5289714cc8` |

162 个真实目录全部满足：读取器解析成功，`decode(encoded)` 后执行 `encode(decoded)` 与原编码目录逐 byte 相等。单元测试另外覆盖固定向量、0～19 字节输入、四种余数和原文件偏移映射。

## Secret 与完整性

该 codec 的 API 不接受 Secret，源码不包含默认 key。输入完整性仍由冻结 Manifest 的逐文件 SHA-256 提供；FNV 只检测解析语义漂移，不承担安全认证。
