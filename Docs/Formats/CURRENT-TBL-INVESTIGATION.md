# 当前客户端 TBL 读取链诊断基线

## 1. 状态与范围

本文记录 P1-09 的可重复诊断结论，不宣告任务完成。当前已经确认新 TBL 的块算法和运行时密钥变更边界，但没有获得经过授权的最终运行时密钥输入，因此尚不能稳定还原代表性新表，也不能确认解密后的压缩和文本编码步骤。

所有证据均从只读的当前客户端目录读取。新工程不链接、不加载、不分发老客户端可执行文件、TBL、更新包或明文残留文件。

## 2. 冻结输入

- 当前 `QY.exe`：5,160,960 bytes，SHA-256 `7087dfa64bedeb8c9a5dfc4518f46261d163136b5bd97f5071f2c5a12cb29a4b`。
- `Table` 与 `CLSVShare` 递归合计 338 张 `.tbl`，40,444,128 bytes。
- 六个 P0 黄金 TBL 样本覆盖 48-byte 最小表、目录最小表、最大技能表、核心物品表、任务表及区域任务变体。
- 明文残留 `CLSVShare/item_tabletemp.csv` 只作为关系证据，不作为可发布表或真值来源。

机器报告保存路径为 `Data/BuildBaseline/p1-09-current-table-investigation.json`。报告只含文件摘要、代码窗口摘要、计数和密钥 SHA-256，不含密钥字节、解密缓冲区或旧资产载荷。

## 3. 密文结构结论

338 张 TBL 均非空且长度为 16 的整数倍，共 2,527,758 个块。全局只有 1,353,326 个不同块，重复出现 1,174,432 次；230 张表存在文件内重复块，44,134 种块跨文件重复，共涉及 346,037 次出现。相同 16-byte 密文块在文件内及文件间大量复用，支持独立块模式，不支持随机 IV 的 CBC 类解释。

证据等级为 L2：结构统计可以证明确定性独立块行为，但算法名称仍需结合读取代码证据。

## 4. 当前读取代码证据

当前 `QY.exe` 中两条表加载路径都执行以下序列：

1. 构造 Rijndael 实例；
2. 以 16-byte 全局缓冲区调用 `setkey`；
3. 读取 `.tbl`；
4. 以参数 `pi=1`、`pj=1` 调用 `decode`。

与已经逐 byte 验证的老读取实现对照后，这对应每个 16-byte 块连续执行两次 AES-128 解密。未观察到 IV、Nonce、认证标签或文件级链式状态。当前二进制的基础密钥与老源码固定密钥不同；两者都不能还原当前黄金 TBL。

更重要的是，当前网络分发器还绑定了两个会修改同一 16-byte 全局密钥的处理器：

- 一个处理器读取 16 个索引并重排全部密钥字节；
- 一个处理器读取四组索引和值，覆盖四个指定密钥字节。

所以磁盘中 `QY.exe` 的基础密钥不是最终运行时密钥。此结论解释了“算法路径相同但当前表无法用磁盘基础密钥解开”的现象。分发槽 958 和 289 来自当前二进制的静态索引推断，不把旧协议枚举名称套用到当前含义。

证据等级为 L2：处理器控制流、循环次数、目标全局缓冲区和表读取调用均来自冻结二进制窗口；消息的业务来源和最终值仍未知。

## 5. 已确认与未确认的处理顺序

已确认：

1. 输入必须为 16-byte 对齐密文；
2. 使用最终运行时 16-byte key；
3. 每块执行两次 AES-128 解密；
4. 独立块之间没有观察到链式 IV/Nonce。

尚未确认：

1. 最终运行时 key 的 16 个字节；
2. 解密后是否还有压缩；
3. 解密后文本是 GBK、GB2312、UTF-8 或其他编码；
4. 新表是否沿用老格式的首字节 padding 长度和末尾零填充。

未取得最终 key 前，不得把老格式的 padding、CRLF、分隔符和编码规则虚假标成新格式事实。

## 6. 残留 CSV 关系

`item_tabletemp.csv` 为 6,551,430 bytes；按老式“1-byte padding 长度 + payload + 零填充”计算只需 6,551,440 bytes 密文，而当前 `item_table.tbl` 为 7,046,704 bytes，多 495,264 bytes，因此二者不可能是同一载荷的直接密文/明文配对。

在忽略首个含 padding 长度的块后，用 ECB 的“相同明文块必得相同密文块”性质对齐检查：前 874 个块内有 196 次重复明文约束全部对应相同密文；第 875 块首次冲突。该结果支持两者具有共同早期内容和相同块边界，但全文件仅 4,152/220,083 次重复约束仍一致，说明后续内容已经增加、删除或发生位移。

因此残留 CSV 可用于字段名、早期内容和 Schema 候选交叉验证，不能覆盖当前加密表，不能充当 P1-09 的完成证据。

## 7. 安全边界与继续条件

- 新工程没有默认 TBL key；读取器继续要求显式 16-byte key。
- 诊断脚本只在内存提取基础 key，输出不可逆 SHA-256 后覆零相关缓冲区。
- 禁止把猜测密钥、当前基础密钥或旧固定密钥写入源码、报告、日志、命令行或备份清单。
- 禁止在未授权时连接现网获取密钥变更消息，禁止关闭 TLS 或绕过服务认证。

P1-09 只有在取得合法的最终运行时参数来源，并让代表性新表稳定还原后才能标记完成。到达该条件后还必须补齐解密后压缩、编码、padding、分隔符和损坏输入测试。
