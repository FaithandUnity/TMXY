# ADR-008：新后端直接采用最终 Linux 架构

- 状态：Accepted
- 日期：2026-08-26

## 决策

新产品后端从首个提交开始采用 Linux x64、C++20、CMake/Ninja、Asio、Protobuf、OCI 和 OpenTelemetry。老 Win32 服务端仅作为只读证据、离线研究与行为 Oracle，不作为产品兼容层，也不沿其工程逐步升级。

## 原因

老工程依赖 VS2008、Win32、ADO/COM、ACE 5.4.2、旧 CRT 和 x86 专有库。把它先改成可运行产品再迁往 Linux，会重复建设网络、数据库、部署和可观测性，并把旧类型扩散到新业务。

## 后果

- 早期必须自行实现新登录/角色纵向切片，不能把老服务当捷径。
- 老逻辑通过源码证据、测试向量和必要的隔离研究构建验证。
- 所有新服务从第一天满足 Linux、容器、PostgreSQL 和工程门禁。
- 不再维护“新旧实现可切换”的生产代码；只保留测试层对照。

## 约束

任何引入 Windows API、ADO、ACE、旧 x86 库或 SQL Server 运行时依赖的 PR 必须被 CI 阻断。
