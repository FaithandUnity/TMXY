# Package 3.0 读取基线

## 结论与范围

P1-06 已对当前客户端中全部 140 个 Package 3.0 文件建立只读解析基线。它们使用与 2.0 相同的 29-byte 外层、14-byte 解码目录前缀和记录字段，但目录变换的一个通道及尾部规则不同。目录结束后直接进入记录声明的连续对象 body；这 140 个容器中没有观察到独立块表或内嵌容器级 checksum 字段。

`TMXY.Package` 只解析容器目录和对象字节区间，不解释 body 类型语义，不声称对象 body 已完成解码、解压或反序列化。原 Package 不复制到仓库或 Git LFS；完整性权威是冻结 Manifest 和逐文件 SHA-256。

## 外层与解码目录

所有整数均为 little-endian。外层字段依次为 uint16 长度、23-byte `QRENDER PACKAGE VER 3.0`、int32 `directory_size`、编码目录和对象 bodies。目录起点固定为文件偏移 29，对象区起点为 `29 + directory_size`。

解码目录字段与已验证的 2.0 记录布局一致：

| 解码偏移 / 顺序 | 字段 | 类型 | 约束 |
|---|---|---|---|
| 0 | directory_prefix | 14 bytes | `030076657264000000010000003f` |
| 14 | object_count | int32 | 非负、未超过配置上限、可由剩余目录容纳 |
| 18 / 重复 | name | uint16 长度 + bytes | 不透明键，同一容器不得重复 |
| 后续 | class_name | uint16 长度 + bytes | 不透明类名字节 |
| 后续 | offset | int32 | 非负 |
| 后续 | size | int32 | 非负 |

记录必须精确消耗目录。按 offset 排序后的对象区间必须从头结束位置连续覆盖到 EOF，不允许重叠、留洞、越界或未声明尾部。

## 目录变换

每个完整 4-byte 编码组 `E0 E1 E2 E3` 解码为：

```text
~E2 ~E3 E0 ~E1
```

尾部不能套用完整组公式，冻结规则为：

| 余数字节 | 解码结果 |
|---:|---|
| 0 | 无尾部 |
| 1 | `E0` |
| 2 | `E0 ~E1` |
| 3 | `~E2 E0 ~E1` |

四种余数均有真实样本和合成回归覆盖。读取器把解码目录中的失败位置反向映射到原文件的编码字节位置。

## 块与完整性边界

在当前 140 个样本中，对象目录结束后没有第二张块表；对象记录本身定义 body 的 offset/size，91,074 个区间均连续覆盖到文件末尾。因此本基线中的“块”指记录声明的对象 body 区间，而不是推断出的额外容器结构。

目录中也没有观察到独立容器 checksum 字段。不得把“未观察到”扩大成对未来版本的永久断言。当前输入完整性由 `client-3.0.0.413.files.jsonl` 的 SHA-256、样本集合 SHA-256 和逐文件 SHA-256 强制；对象 body 内部是否自带校验属于后续具体对象格式合同。

## 冻结全样本结果

| 属性 | 冻结值 |
|---|---:|
| 实样文件数 | 140 |
| 实样集合 SHA-256 | `9e6872a12464bcbe7c98de2cd96a9ad3d831156a14a7b50b1a2dd07ec75260dd` |
| 文件总大小 | 36,333,329 bytes |
| 目录总大小 | 4,143,928 bytes |
| 记录总数 | 91,074 |
| 最少 / 最多记录数 | 1 / 10,726 |
| 聚合元数据 FNV-1a 64 | `f8ec20e8fff7b975` |

实样集合 SHA-256 覆盖按路径排序的 `path|size|sha256` 行。聚合元数据指纹覆盖相对路径、版本、记录顺序、名称、类名、偏移和大小，用于发现解析语义漂移，不替代安全哈希。

## 错误与安全边界

`PackageV3Error` schema 版本为 1，提供稳定错误码、原文件绝对偏移、可选记录序号、字段上下文和可选 bounded-reader 错误码。它拒绝截断、错误版本、非法目录大小、前缀不符、非法计数、负 offset/size、重复名称、目录尾随字节和不完整对象区间。
