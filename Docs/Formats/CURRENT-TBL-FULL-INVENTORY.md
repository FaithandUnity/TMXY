# Current TBL full inventory

P2-04 inventories every encrypted TBL in the frozen `qy-3.0.0.413` sandbox.
The committed machine report is
`Data/Inventory/p2-04-current-table-inventory.json`; it is regenerated by
`Tools/TMXY.Table/New-FullCurrentTableInventory.ps1`.

## Result

The frozen population contains 338 files and 40,444,128 ciphertext bytes:

- 225 active tables decode with the P1-09 authorized runtime key;
- 113 older shadows do not decode with the active key, and every one has a
  newer, successfully decoded replacement;
- no active or unclassified table remains unresolved.

The active tables contain 214,885 physical data rows and 29,658,173 payload
bytes. Encoding is explicit per table: 165 ASCII, 59 strict GBK, and one strict
UTF-8 table (`CLSVShare/ArenaLevel.tbl`). There are 181 fixed-width and 44
variable-width comma-delimited physical schemas. Variable width is reported as
evidence and is not silently padded or normalized.

Each entry freezes the relative path, ciphertext length and SHA-256, timestamp,
source group/version role, lifecycle, decode result, encoding, physical row and
column metrics, header hash/quality counts, empty-field counts, primary-key
candidate classification, and replacement evidence when applicable.

## Key and schema boundaries

The generator reads the 16-byte key only from the operating-system credential
store, verifies its P1-09 fingerprint, and binds the run to the frozen `QY.exe`
and P1-09 capture-evidence hashes. It does not read an environment variable or
place the key on a command line. Key bytes, plaintext rows, headers, field
identifiers, and field values are never written to the report and all byte
buffers are cleared.

Primary-key results are candidates, not authoritative product schemas. A
nonempty unique first field is preferred; otherwise the generator checks
contiguous prefixes through eight columns and then distinguishes a full-row
unique table from a table containing duplicate physical rows. P2-07 owns the
semantic key/type/range/foreign-key definitions.

Historical shadows intentionally retain unavailable row, column, encoding,
and key values. Guessing an obsolete key would cross the evidence boundary.
Each such entry instead records the failed active-key classification plus the
path, hash, timestamp, and freshness of its verified replacement.

## Reproduction

Run the generator only against the read-only sandbox below `Data/Backups`, then
run `Tests/Contract/Test-FullCurrentTableInventory.ps1`. The contract needs no
Secret and independently validates all 338 committed entries, totals,
lifecycles, encodings, representative schemas, source binding, replacement
links, and non-emission guarantees.
